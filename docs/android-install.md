# Android 폰에 설치하기 (Spotify·YouTube Music·Apple Music)

Android 폰에서 이 앱을 Spotify·YouTube Music·Apple Music 앱과 함께 쓰는 절차다. 결정 근거는 [plan.md](plan.md) D-41·D-42, 연동 방식은 [platform-support.md](platform-support.md) §2.9.

```
[Windows PC] ── 코드 올리기 ──▶ [GitHub] ── Linux 서버에서 빌드 ──▶ .apk
     ▲                                                          │
     └──────────── 내려받기 ◀───────────────────────────────────┘
[Android 폰] ◀── USB·클라우드·메신저 등으로 .apk 옮겨 설치
```

> iPhone과 달리 **7일마다 다시 설치할 필요가 없다**. 새 버전도 지우지 않고 덮어 설치하면 데이터가 남는다(§4).
> 아직 실제 Android 기기에서 확인하지 않았다(MV-AND-INSTALL-01, MV-PB-AND-01~03).

## 0. 준비물
| 항목 | 비고 |
|---|---|
| GitHub 저장소 | iPhone 빌드에 쓰는 저장소(`alsrb417352-glitch/lyrics-companion`) 그대로 |
| Android 폰 | Android 7.0 이상 |
| 재생 앱 | Spotify·YouTube Music·Apple Music 중 쓰는 앱(각 앱의 계정·구독은 그 앱에서) |

## 1. 빌드 설정 올리기 (처음 한 번)
1. 빌드 설정 파일이 `.github\workflows\android-apk.yml`에 있는지 확인한다(없으면 복사).
   ```powershell
   cd "E:\ai data\노래가사앱(로컬)"
   Copy-Item ci\android-apk.yml .github\workflows\android-apk.yml
   ```
2. GitHub Desktop → 바뀐 파일 확인 → Summary 입력 → **Commit to main** → **Push origin**.
   - Linux 러너는 공개 저장소에서 무료다(비공개 저장소도 macOS보다 훨씬 적게 쓴다).

## 2. 앱 빌드하기
1. GitHub 웹 → 저장소 → **Actions** → 왼쪽 `android-apk` → **Run workflow** → Run.
   (이후에는 `main`에 앱 코드를 올릴 때마다 자동으로 빌드된다.)
2. 15~40분 기다린다(Gradle 첫 빌드가 오래 걸림). `core-check`(검사) → `build-android`(빌드·APK 검사) 순서.
3. 끝나면 실행 화면 아래 **Artifacts**의 `lyrics-companion-android-apk`를 내려받아 압축을 푼다 → `LyricsCompanion-0.1.0-<번호>-android.apk`
4. 실패하면 `gradle-log`를 내려받아 Claude에게 보여 준다(Kotlin 코드를 처음 컴파일하는 단계라 첫 빌드는 실패할 수 있다).

## 3. 폰에 설치
1. `.apk` 파일을 폰으로 옮긴다(USB 연결 후 다운로드 폴더에 복사, 또는 Google Drive 등).
2. 폰의 **파일** 앱에서 `.apk`를 누른다 → "출처를 알 수 없는 앱" 안내가 나오면 **설정** → 그 파일 앱에 **이 출처 허용** → 뒤로 → **설치**.
3. Google Play 프로텍트 경고가 나오면 "세부정보 › 무시하고 설치"(직접 빌드한 앱이라 Play 스토어에 없어서 나오는 경고).
4. **가사 보조** 앱 실행 → "재생 앱 연동" 화면 → **알림 접근 설정 열기** → 목록에서 **가사 보조** 켜기 → 허용.
   - "제한된 설정" 안내가 나오면(Android 13 이상, 파일로 직접 설치한 앱): 앱의 **앱 정보 열기** 버튼 → 오른쪽 위 **⋮** → **제한된 설정 허용** → 다시 알림 접근을 켠다.
   - 이 권한은 다른 앱의 "지금 재생 중" 정보를 읽기 위한 Android의 조건이다. 앱은 **알림 내용(메시지·발신자 등)을 읽거나 저장하지 않는다**(docs/security.md §3).
5. 앱으로 돌아와 Spotify·YouTube Music·Apple Music에서 곡을 재생하면 지금 재생 탭에 가사가 뜬다. 헤더의 작은 표시(예: "Spotify")가 지금 따르는 앱이다.

## 4. 새 버전으로 업데이트
- 새로 빌드한 `.apk`를 §3처럼 **지우지 말고 그대로 설치**한다(덮어 설치). 저장된 가사·번역·설정·API 키가 남는다.
  모든 빌드가 같은 서명 키(Expo 템플릿 디버그 키)로 서명되어 덮어 설치가 된다.
- 그래도 "앱이 설치되지 않음"이 나오면 서명이 다른 것이다(다른 PC·다른 방법으로 만든 APK 등). 앱을 지우기 전에 **설정 › 백업 › 백업 파일 만들기**로 저장해 두고, 다시 설치한 뒤 **백업 가져오기**로 되살린다(API 키는 백업에 없으므로 다시 입력).
- iPhone·PC에서 만든 백업 파일도 그대로 가져올 수 있다. 같은 곡을 Android에서 처음 재생하면 "저장된 곡 중 같은 녹음이 있나요?"가 한 번 나온다 — 서비스가 달라(iPhone은 Apple Music 스토어 ID, Android는 Spotify·YouTube Music 곡 ID) 자동으로 같은 곡이라고 단정하지 않기 때문이다(불변조건 6). "이 곡이 맞아요"를 누르면 다음부터는 바로 연결된다.

## 5. 보안 주의
- 지금 APK는 **공개된 디버그 키**로 서명된다. 개인 사이드로드에는 문제가 없지만, 같은 키로 서명된 다른 사람의 APK도 덮어 설치될 수 있으므로 **이 저장소의 Actions에서 받은 APK만 설치**한다. 다른 사람에게 배포하려면 자체 서명 키로 바꾼다(배포 전 권리 검토와 함께, D-07).
- AI API 키는 앱의 설정 화면에서만 입력한다(Android Keystore로 암호화해 보관, Google 자동 백업에서 제외). 채팅·문서·GitHub에 붙여 넣지 않는다.
- 앱이 요청하는 권한: 인터넷, 알림 접근(사용자가 설정에서 켬). 다른 앱 위에 그리기·저장소·진동 권한은 막아 두었다.

## 6. 문제 해결
| 증상 | 확인할 것 |
|---|---|
| "재생 앱 연동" 화면에서 넘어가지 않음 | 설정 › 알림 › 기기 및 앱 알림(또는 "알림 접근")에서 가사 보조가 켜져 있는지. 켠 뒤 앱으로 돌아오면 자동으로 다시 확인한다 |
| 알림 접근 스위치가 회색(제한된 설정) | §3-4의 "제한된 설정 허용" |
| 곡을 재생해도 "…에서 곡을 재생하세요"만 보임 | 그 앱이 실제로 재생 중인지, 알림 창에 그 앱의 재생 컨트롤이 보이는지(미디어 세션이 없으면 읽을 수 없음). 광고·팟캐스트는 곡으로 보지 않는다 |
| 한동안 쓰다가 가사가 멈춤 | 제조사 배터리 최적화가 재생 앱·이 앱을 멈췄을 수 있다. 설정 › 배터리에서 두 앱을 "제한 없음"으로(MV-PB-AND-02) |
| 플레이리스트 탭이 비어 있음 | Android 탭은 지금 따르는 앱의 **재생 목록(대기열)**을 보여 준다. 그 앱에서 플레이리스트·앨범을 재생한 뒤 새로고침. 앱에 따라 재생 목록을 알려 주지 않을 수 있다 |
| 검색 탭에서 고른 곡과 다른 버전이 재생됨 | Android에서는 재생 앱이 자기 검색 결과에서 곡을 고른다. 가사는 실제로 재생된 곡 기준이라 섞이지 않는다. 정확한 곡은 그 앱에서 직접 재생 |
| 가사가 안 나오거나 다른 곡 가사가 나옴 | 지금 재생 › "후보 보고 고르기" 또는 ⋯ › "가사 바꾸기"로 직접 고른다. YouTube Music의 뮤직비디오는 제목 표기가 달라 못 찾을 수 있다 → "가사 직접 찾기"·"가사 직접 등록" |
