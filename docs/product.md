# 제품 정의: 번역 가사 보조 앱

## 1. 목표
**Apple Music**으로 **일본어·영어 노래**를 들을 때, 현재 곡에 맞는 **한국어 번역 가사**(일본어는 발음 포함)를 **자동 싱크**로 보여주는 iPhone **보조 앱**.
음악 재생은 Music 앱이 하고, 우리 앱은 가사를 보여주며 곡 선택(검색·보관함 플레이리스트)·재생 제어도 한다. 우리 앱에서 곡이나 플레이리스트를 고르면 Music 앱을 열지 않아도 바로 재생된다.
> 범위(2026-10-04 사용자 결정, docs/plan.md D-17): iPhone은 Apple Music 전용. Spotify·YouTube Music은 iPhone에서 지원하지 않는다(공개 OS API 없음).
>
> **Android 버전(2026-10-14 사용자 요청, D-41)**: Android 폰에서는 **Spotify·YouTube Music·Apple Music 앱**이 재생할 때 같은 화면·기능(자동 싱크 가사·번역·발음·편집·싱크 기록·가사 직접 등록·백업, 플레이리스트 탭·검색 탭·설정)을 쓴다. 재생 정보는 Android 미디어 세션(알림 접근 권한)으로 읽고, 플레이리스트 탭은 재생 앱의 지금 재생 목록(대기열)을, 검색 탭은 고른 앱에 검색 재생을 요청한다. 판단 로직은 iPhone과 같은 core이며 데이터는 백업 파일로 주고받는다.
>
> **PC 버전(2026-10-06 사용자 요청, D-36)**: Windows의 Chrome/Edge에서 **Apple Music 웹 플레이어(music.apple.com)** 를 쓸 때 같은 기능을 쓰도록 **브라우저 확장 프로그램**(`apps/pc-extension`)으로 제공한다. 가사는 브라우저 사이드 패널(또는 따로 띄운 창)에 나오고, 재생 위치는 웹 플레이어에서 직접 읽는다. 판단 로직은 iPhone 앱과 같은 core를 쓰며, 데이터는 백업 파일로 iPhone과 주고받는다.

## 3. 사용자 흐름
- **F1 자동 연동**: Music 앱에서 재생(또는 우리 앱에서 곡 선택) → 우리 앱이 현재 곡 감지 → 저장본이 있으면 즉시 표시(네트워크 없음) → 없으면 LRCLIB 조회(현지화 표기면 원어 표기로 재조회) → 자동 싱크 → 번역 정책에 따라 번역 표시.
- **F1b 플레이리스트에서 바로 듣기**(2026-10-05): 플레이리스트 탭 → 보관함 플레이리스트 선택 → 재생/셔플/곡 탭 → Music 앱이 그 플레이리스트를 대기열로 재생(앱 전환 없음) → 지금 재생 탭으로 이동해 가사 표시.
- **F2 곡 식별 확인**: 저장된 곡과 같은 녹음인지 불확실(서비스가 다르고 ISRC 없음) → 후보 표시 → 사용자가 "같은 곡"/"다른 곡" 선택.
- **F3 가사 확인·직접 선택**: 가사를 자동으로 확정하지 못함(가수 표기가 다른 후보만 있음 등) → 후보 목록(자동 조회와 같은 우선순위로 정렬, 줄마다 "싱크 가사 · 원문 · 한국어 뜻 · 한글 발음"·곡이 다를 수 있다는 경고·첫 원문 줄) → 사용자가 선택 또는 직접 검색 → 저장. 이미 표시 중인 가사가 틀리면 "가사 바꾸기"로 교체(이전 판본 보존).
- **F4 번역 요청**: 자동 번역 꺼짐 상태에서 "번역" 버튼 → 전송될 내용(가사 원문 행)·예상 비용 안내 확인 → 요청 → 결과 저장. 실패하면 사유와 재시도 범위(번역만/발음만) 표시.
- **F5 사용자 번역**: 직접 입력·붙여넣기 또는 TXT/LRC 가져오기 → 미리보기 → 행 수·시간이 맞지 않으면 행 연결·시간 조정 화면 → 저장. 저장된 사용자 번역은 AI가 덮어쓰지 않는다.
- **F6 재번역·발음 생성**: 곡 메뉴의 명시적 버튼으로만 실행. 결과는 새 버전, 사용자 번역은 그대로 우선.
- **F5b 원문 내보내기**(2026-10-05): 지금 재생 › 도구 › 원문 txt 내보내기 → 공유 시트(파일에 저장, 다른 앱) → 바깥에서 번역 → "번역 직접 입력"에 붙여넣기(빈 줄 제외 행 수가 같으면 자동으로 칸이 채워짐).
- **F5c 수동 싱크**(2026-10-05): 시간 정보가 없거나 틀린 가사 → "싱크 직접 기록" → 노래를 들으며 각 줄이 시작될 때 큰 버튼 탭(되돌리기·처음부터) → 저장. 이후 이 곡은 기록한 시간으로 넘어가고, 번역·발음은 그대로. "원래 싱크로 되돌리기"로 해제.
- **F5d 소리로 싱크 맞추기**(2026-10-23, D-44, iPhone·iOS 26 이상): 시간 정보 없는 가사 → "소리로 맞추기" → 안내 확인(이어폰 빼고 스피커로, 조용한 곳) → 시작 → 곡이 처음부터 재생되고 앱이 마이크로 듣는다(처음 한 번 마이크 권한·언어 모델 내려받기) → 곡이 끝나면 맞춰 바로 적용("소리로 맞춘 싱크" 표시, 몇 줄을 소리로 찾았는지 안내). 틀린 곳은 "싱크 직접 기록"으로 고치고 "내 싱크 끄기"로 되돌린다. 플레이리스트 화면의 "싱크 없는 곡 소리로 맞추기"는 시간 정보 없는 가사가 저장된 곡만 대기열에 넣고 차례로 재생하며 곡마다 맞춘다.
- **F8 PC(Windows) — Apple Music 웹**(2026-10-06): Chrome/Edge에서 music.apple.com 로그인 → 도구 모음의 확장 프로그램 아이콘으로 사이드 패널 열기 → 웹 플레이어에서 재생하면 패널에 가사가 자동 싱크로 표시(F1과 같은 규칙). 대기열 탭: 웹 플레이어에서 재생한 플레이리스트·앨범의 현재 대기열로 가사 원문 일괄 받기·번역 묶음(iPhone 플레이리스트 탭과 같은 기능). 설정 › 백업으로 iPhone 데이터 가져오기. AI 키는 Windows 보안 저장소 도우미(1회 설치)에 저장.
- **F7 설정**: AI 제공자·모델·API 키 등록/교체/삭제(키는 끝 4자리만 표시), 자동 번역 동의, 일일 요청 상한, 표시 설정(번역/발음), 데이터 내보내기·삭제.

## 4. 가사 화면 설계 원칙 (자체 디자인)
Apple Music 가사 화면의 **경험**을 참고하되, Apple 로고·아이콘·서체 등 전용 자산은 쓰지 않는다(REQ-UI-06).
- 큰 글자, 넉넉한 줄 간격, 현재 행 강조(굵기·불투명도), 지난 행·다음 행은 낮은 대비지만 **WCAG 대비 4.5:1 이상** 유지.
- 원문(항상) → 발음(선택) → 번역(선택)을 **한 묶음**으로 표시. 묶음 단위로 강조·스크롤.
- 현재 행이 화면 상단 1/3 지점에 오도록 부드럽게 자동 스크롤. **동작 줄이기**가 켜져 있으면 애니메이션 없이 위치만 이동.
- 사용자가 직접 스크롤하면 자동 추적을 멈추고 "현재 가사로" 버튼 표시. 버튼을 누르거나 일정 시간(예: 5초) 조작이 없으면 복귀.
- 시스템 글자 크기(Dynamic Type/글꼴 크기)를 따르고 앱 내 크기 조절도 제공. 화면 읽기(VoiceOver/TalkBack)는 묶음 하나를 "원문. 발음 …. 번역 …"으로 읽는다(core `accessibilityLabel`).
- 행 단위 싱크만 표시(원문 타임스탬프, 사용자가 직접 기록한 시간, 또는 소리로 맞춘 시간 — A-8). 단어 단위 강조는 하지 않는다. 위치를 모르면 진행 표시(강조·자동 스크롤)를 하지 않고 "재생 위치를 알 수 없음"을 표시.
- 재생 제어 바: 지원되는 조합에서만 표시(재생/일시정지, ±10초, 이전/다음, 진행 막대로 탐색).

## 5. 표시 규칙
- 영어 곡: 원문 + 번역. 일본어 곡: 원문 + 발음(일본어 문자가 있는 행) + 번역. 한국어 곡: 원문만.
- 번역 선택 우선순위(고정, 2026-10-19 사용자 결정으로 한 단계 추가 — D-43): **사용자 번역 → 저장된 AI 번역 → 가사에 포함된 번역(가사 출처에 원문과 함께 있던 한국어 뜻) → 원문만 → (조건 충족 시) 신규 AI 번역**. 가사에 포함된 번역이 있으면 AI를 자동으로 부르지 않고, AI 번역은 사용자가 직접 요청할 때만 그 위에 보인다. 발음도 같은 순서(내 발음 → AI 발음 → 가사에 포함된 발음).
- 가사 선택 우선순위(2026-10-19 사용자 결정, D-43): **① 재생 중인 곡과 맞는지(최우선) → ② 싱크 가사 → ③ 원문 가사 → ④ 한국어 뜻 → ⑤ 한글 발음**이 있는 가사 순서로 고른다. 곡이 맞는지 불확실하면(가수 표기가 다름 등) 자동으로 고르지 않고 사용자에게 후보로 보인다.
- 사용자 번역이 일부 행만 있으면 그 행만 번역을 표시하고 나머지는 원문만. AI로 채우지 않는다.

## 6. 요구사항과 수용 기준
상태와 테스트 연결은 [`traceability.md`](traceability.md)(자동 생성)에서 확인한다. 원본 레지스트리: [`requirements.json`](requirements.json).

### 앱 구조·재생 연동
- **REQ-APP-01** 보조 앱 구조. 수용 기준: 스트리밍 앱이 재생 중일 때 우리 앱 가사 화면이 해당 곡 가사를 보여준다. 우리 앱은 음원을 재생하지 않는다(iOS Apple Music 제어는 Music 앱에 명령).
- **REQ-PB-01** 자동 감지. 수용 기준: 지원 조합(docs/platform-support.md §1)에서 곡 변경 후 2초 안에 새 곡을 인식, 재생 위치 오차 ±500ms 이내(실기기 측정), 일시정지·탐색 반영.
- **REQ-PB-02** 대체 흐름. 수용 기준: 권한 거부 시 앱이 멈추지 않고 허용 방법을 안내. 가사 자동 조회가 확정하지 못하면 후보·직접 검색으로 사용자가 고른다(같은 녹음인지 불확실하면 자동 적용하지 않음). 위치를 모르면 진행 표시 없음.
- **REQ-PB-03** 재생 제어. 수용 기준: 지원 조합에서 재생/일시정지/탐색/이전/다음이 동작하고, 지원하지 않는 명령의 버튼은 숨긴다.
- **REQ-PB-05** 앱 안 곡 선택(iOS Apple Music). 수용 기준: 우리 앱에서 곡을 검색·선택하면 Music 앱이 그 곡을 재생하고(Apple Music 구독 필요), 사용자가 Music 앱을 따로 열 필요가 없다. 검색 응답은 불신 데이터로 검증한다. 재생할 수 없는 곡은 오류를 알린다.
- **REQ-PB-07** Android 재생 앱 연동(Spotify·YouTube Music·Apple Music, D-41). 수용 기준: 사용자가 알림 접근을 허용하면 세 앱 중 재생 중인 앱의 현재 곡·재생 위치·상태를 자동으로 읽어 iPhone과 같은 자동 싱크 가사를 보여 주고, 재생·일시정지·탐색·이전/다음·줄 탭 이동을 그 앱에 보낸다. 알림 내용과 세 앱 밖의 미디어 정보는 읽지 않는다. 위치를 모르거나(앱이 -1을 줌) 오래된 상태면 진행을 표시하지 않는다. 광고·팟캐스트는 곡으로 보지 않는다. 다른 서비스의 같은 곡(예: iPhone 백업의 곡)은 자동으로 같다고 단정하지 않고 후보 확인을 거친다. 권한이 없으면 이유와 설정 방법(제한된 설정 포함)을 안내한다.
- **REQ-PB-08** Android 플레이리스트·검색 탭(D-41). 수용 기준: 플레이리스트 탭은 따르는 재생 앱의 지금 재생 목록을 iPhone 플레이리스트 화면 모양으로 보여 주고, 곡부터 재생·재생·셔플·가사 원문 일괄 받기·번역 묶음을 iPhone과 같은 규칙으로 제공한다(재생 목록 곡은 지금 재생과 같은 곡 식별 규칙). 앱이 재생 목록을 주지 않으면 그렇게 안내한다. 검색 탭은 설치된 재생 앱 중 하나를 고르고, 고른 곡을 그 앱에 검색 재생으로 요청한다(가사는 실제로 재생된 곡 기준). 요청할 수 없으면 오류를 알린다.
- **REQ-PB-06** 보관함 플레이리스트에서 바로 재생(iOS Apple Music). 수용 기준: 보관함 플레이리스트(직접 만든 것·보관함에 추가한 Apple Music 플레이리스트) 목록과 곡 목록을 보여 주고, 재생·셔플·곡 탭으로 Music 앱이 그 플레이리스트를 대기열로 재생한다(Music 앱을 열 필요 없음, 다음/이전 곡은 플레이리스트 순서). MusicKit 카탈로그 API·개발자 토큰 없이 동작(무료 서명). 네이티브 원시 값은 검증한다(ID는 문자열 UInt64). 재생할 수 없으면 오류를 알린다.
- **REQ-PC-01** PC(Windows Chrome/Edge) Apple Music 웹 플레이어 연동(2026-10-06 사용자 요청, D-36). 수용 기준: 확장 프로그램을 설치하고 music.apple.com에서 재생하면 사이드 패널(또는 따로 띄운 창)이 현재 곡을 인식해 iPhone 앱과 같은 규칙(곡 식별·저장본 우선·번역 정책·싱크·편집·수동 싱크·원문 TXT·대기열 가사 일괄 받기·번역 묶음·백업)으로 가사를 보여 준다. 재생 위치는 웹 플레이어의 실제 오디오 위치로 맞추고, 미리듣기(로그인·구독 없음)·불러오는 중·연결 끊김이면 진행을 꾸며내지 않는다(위치 모름 표시). 곡 ID·ISRC는 웹 플레이어 값을 검증해 쓰고, iPhone과 같은 스토어 ID면 같은 곡으로 연결된다(백업을 옮긴 뒤 재생해도 가사·AI 재조회 0회). 패널은 재생 제어 명령 외에는 Apple Music 페이지에 아무것도 보내지 않고, 페이지 계정 정보·토큰을 읽지 않는다. 같은 저장소를 두 화면에서 동시에 열지 않는다.
- **REQ-PC-02** PC의 AI API 키는 Windows 보안 저장소에만(불변조건 8, 2026-10-06 사용자 선택 "Windows 보안 저장소 도우미"). 수용 기준: 키는 네이티브 메시징 도우미가 Windows DPAPI(현재 사용자 범위)로 암호화해 사용자 프로필 폴더에 보관하고, 확장 프로그램 저장소(IndexedDB)·설정·로그·백업에는 들어가지 않는다. 도우미는 등록한 확장 프로그램 ID만 부를 수 있고(경로 조작 이름 거부), 설치·제거는 현재 사용자 범위(HKCU)만 바꾼다. 도우미가 없으면 키 저장을 거부하고 AI 번역은 "제공자 없음"으로 건너뛴다. AI 제공자 주소는 사용자가 허용한 주소로만 요청이 나간다.
- **REQ-PB-04** 오버레이. 수용 기준: OS 지원·정책 확인(MV-OVL-01) 전에는 제공하지 않는다. 제공 시 기본 화면과 별도 설정으로 켠다.

### 가사 조회·식별
- **REQ-LY-01** LRCLIB 조회. 수용 기준: 모든 요청에 앱 식별 헤더. 요청은 순차·최소 간격(기본 300ms). 429/503 시 Retry-After 동안 재요청 없음. JSON 아닌 응답·형식 오류는 오류로 처리.
- **REQ-LY-02** 가사 상태. 수용 기준: 싱크/일반/연주곡/없음/잘못된 LRC를 구분해 표시. 잘못된 LRC는 일반 가사가 있으면 대체하고 알림, 없으면 저장하지 않는다.
- **REQ-LY-03** 곡 식별. 수용 기준: 같은 서비스의 같은 곡 ID 또는 ISRC+길이±2초+버전 태그 일치 시 자동 연결. 메타데이터만 일치하면 후보 확인. 라이브·리믹스·TV size·다른 언어 버전은 다른 곡. 가사 레코드도 버전·길이가 맞지 않으면 쓰지 않는다.
- **REQ-LY-04** 원문 변경. 수용 기준: 새 원문은 새 판본으로 저장되고 기존 판본·번역은 보존. 활성 판본 변경은 사용자 확인으로만. (현재: 보존·비자동 전환은 구현, 변경 감지·확인 UI는 미구현)
- **REQ-LY-05** 플레이리스트 가사 원문 일괄 받기(2026-10-05 사용자 요청 "곡마다 받기 불편 → 플레이리스트 곡 일괄 받기"). 수용 기준: 플레이리스트 화면에서 한 번에 모든 곡의 원문을 LRCLIB에서 받아 저장한다(진행률·취소, 앱을 닫거나 취소해도 이미 받은 곡은 유지, 다시 실행하면 남은 곡만). 가사가 이미 저장된 곡은 조회하지 않고 판본·번역을 바꾸지 않는다. 같은 녹음인지 불확실한 곡(저장된 곡 후보)·확정하지 못한 가사 후보는 자동 적용하지 않고 "확인 필요"로 표시한다(불변조건 6). AI(번역·발음)는 호출하지 않는다. 요청 간격·Retry-After를 지키고, 오프라인·연속 오류·긴 요청 제한이면 멈추고 이유를 알린다. 받은 곡은 나중에 재생할 때 네트워크 조회 없이 바로 표시된다.
- **REQ-LY-06** 가사 직접 등록(2026-10-12 사용자 요청 "LRCLIB 직접 검색으로도 못 찾으면 텍스트 파일 또는 직접 입력으로 가사 등록", D-40). 수용 기준: 가사 고르기·"가사를 찾지 못했습니다" 화면에서 TXT/LRC 파일을 불러오거나 텍스트를 붙여 넣어 현재 곡의 원문으로 저장할 수 있다(iPhone·PC). 저장 전에 미리보기(싱크/시간 정보 없음·줄 수·경고)를 보여 주고 사용자가 눌러야 저장한다. 줄 앞 시간 표시가 있으면 그 시간 그대로 싱크 가사, 없으면 시간 정보 없는 가사로 저장하며, 시간 없는 줄이 섞이거나 시간이 틀린 LRC는 저장하지 않고 고칠 줄을 알려 준다(사용자가 고르면 시간 표시를 지운 일반 가사로 저장 — 시간을 짐작해 채우지 않음, 불변조건 5). 기존 판본·번역은 보존하고, 같은 내용을 다시 등록하면 새 판본을 만들지 않는다. 저장한 가사는 재시작·오프라인에서도 네트워크 조회 없이 표시되고 백업에 포함된다. 파일·입력은 불신 데이터로 크기·줄 수·줄 길이를 검사하고 가사 속 문장을 명령으로 따르지 않는다.
- **REQ-LY-07** 가사 후보 우선순위(2026-10-19 사용자 요청 "재생 중인 곡과 맞는 것이 최우선, 곡이 맞으면 싱크 → 원문 가사 → 한국어 의미 → 발음 지원 순서", D-43). 수용 기준: 자동 조회·플레이리스트 일괄 받기·가사 고르기 목록이 같은 순위를 쓴다. 제목·녹음 버전·길이(±2초)가 다르면 자동으로 고르지 않고, 가수 표기가 다르면 자동 적용 없이 후보로 묻는다. 곡이 맞는 후보끼리는 싱크 가사 → 원문(곡 원어 문자) 가사 → 한국어 뜻 → 한글 발음이 있는 것이 앞이다. 처음 찾은 가사보다 나은 업로드가 있으면 그것을 고르고, 비교용 추가 조회가 실패해도 찾은 가사를 잃지 않는다. 가사 고르기 목록은 줄마다 무엇이 있는지와 곡이 다를 수 있다는 경고를 보인다.
- **REQ-LY-08** 가사에 포함된 한국어 뜻·발음(2026-10-19 사용자 결정 "번역·발음 칸으로 나누기", D-43). 수용 기준: 원문과 한국어 뜻·한글 발음 줄이 번갈아 적힌 가사는 구조가 확실할 때만 원문 줄만 가사로 저장하고, 뜻은 번역 칸·발음은 발음 칸에 "가사에 포함된" 것으로 표시한다(원문 시간은 그대로, 한국어 줄 시간은 쓰지 않음). 이 번역이 있으면 AI를 자동으로 부르지 않는다. 표시 순서는 내 번역 → AI 번역(직접 요청) → 가사에 포함된 번역 → 원문이며 가사에 포함된 번역은 지우지 않는다. 판본과 한 번에 저장하고 백업에 포함한다. 확실하지 않은 가사(한국어 곡·구조가 들쭉날쭉)는 나누지 않는다.

### 싱크
- **REQ-SY-01** 수용 기준: 원문 타임스탬프(또는 REQ-SY-05의 사용자 기록 시간, REQ-SY-06·07의 소리로 맞춘 시간)로만 현재 행 결정. 번역·발음은 행 ID로 연결. AI 응답에 시간 값이 있어도 무시. 단어 단위 싱크 원본도 행 단위로 표시.
- **REQ-SY-02** 수용 기준: 일시정지 중 위치 고정, 탐색 즉시 반영, 곡 변경 시 이전 곡 위치를 적용하지 않음, 마지막 측정 후 60초 넘게 새 측정이 없으면 위치 미확정(백그라운드 복귀 시 재측정).
- **REQ-SY-03** 수용 기준: 곡별 보정값(±30초 범위)이 저장되고 재실행 후 같은 곡에만 적용.
- **REQ-SY-04** 수용 기준: 시간 정보 없는 가사는 (사용자 싱크 기록이 없으면) 정적 화면(강조·자동 스크롤 없음).
- **REQ-SY-05** 수동 싱크(2026-10-05 사용자 요청·결정, D-28). 수용 기준: 시간 정보 없는 가사·시간이 틀린 싱크 가사 모두 탭으로 줄 시작 시간을 기록해 저장할 수 있다. 기록 시각은 버튼을 누른 순간의 실제 재생 위치뿐이다(AI·추정으로 만들지 않음). 빈 줄은 기록 대상이 아니다. 기록은 앞에서부터 연속, 시각이 앞 줄보다 이를 수 없다. 끝까지 기록하지 않으면 기록하지 않은 줄은 강조하지 않는다. 가사 판본·번역·발음은 바뀌지 않고, 기록은 새 버전으로 추가(되돌리기 가능)되며 재실행·백업 후에도 같은 곡에만 적용된다. 저장 시 AI·네트워크 호출 0회.
- **REQ-SY-06** 소리로 싱크 맞추기 — 지금 곡(2026-10-23 사용자 요청 "싱크 없는 가사를 자동으로 싱크", 방식 선택 "소리 듣고 자동 맞추기"·적용 "바로 적용, 틀리면 고치기", D-44). 수용 기준: 시간 정보 없는 가사(plain)에서만 쓸 수 있고, 사용자가 시작했을 때만 마이크로 듣는다(곡을 처음부터 재생). 들은 소리는 저장·전송하지 않고 인식은 기기 안에서만 한다. 알아들은 말을 가사 글자(일본어·한국어)·단어(영어) 순서와 맞춰 줄 시작 시각을 정하고, 못 알아들은 줄은 앞뒤 기준점 사이를 글자 수·연(빈 줄)·다시 들린 소리로 채운다. 소리를 듣지 않은 뒤쪽 줄에는 시간을 만들지 않는다. 다른 곡·잡음처럼 가사와 순서가 맞지 않으면(뒤집은 가사로 맞춘 결과와 차이가 작으면) 또는 소리로 찾은 줄이 너무 적으면 저장하지 않는다. 결과는 "소리로 맞춘 싱크"(method auto)로 새 버전 저장·바로 적용, 곡별 보정 0, 가사 판본·번역은 그대로, 되돌리기·탭으로 고치기 가능, 재실행·백업 후 유지. 탭으로 기록한 싱크가 있으면 사용자가 확인했을 때만 바꾼다(확인 전에는 듣지도 않음). 마이크 거부·이어폰/블루투스 재생이면 듣지 않고, 듣는 중 이어폰으로 바뀌면 저장 없이 멈춘다. "여기까지 저장"은 들은 곳까지만 시간을 만든다. AI·네트워크 호출 0회.
- **REQ-SY-07** 플레이리스트 소리로 싱크 맞추기(2026-10-23 사용자 선택 "지금 곡 + 플레이리스트 일괄", D-44). 수용 기준: 저장된 가사가 시간 정보 없는 가사이고 싱크 기록(탭·소리)이 없는 곡만 대상(저장소만 읽음). 대상 곡만 Music 앱 대기열에 넣어 처음부터 차례로 재생하고(반복·셔플 끔), 곡이 넘어갈 때마다 그 곡의 소리로 맞춰 저장한다(곡 언어로 인식 전환). 싱크 가사·탭 기록·가사 없음·연주곡·지원하지 않는 언어·중복은 건너뛰고 이유를 보인다. 멈추면 끝까지 들은 곡만 저장하고 듣던 곡은 저장하지 않는다. 듣는 동안 가사 판본이 바뀌거나 싱크 기록이 생긴 곡은 저장하지 않는다. 동시에 하나만 실행.

- **REQ-TR-02** 수용 기준: §5 표시 규칙.
- **REQ-TR-03** 수용 기준: 가정 A-1~A-3. 발음은 행별 한글 독음, 사용자 수정 가능.
- **REQ-TR-04** 수용 기준: 우선순위 고정(§5).
- **REQ-TR-05** 수용 기준: 저장 번역이 있으면 재생·앱 재시작·표시 변경·모델/프롬프트/제공자 변경에도 AI 호출 0회.
- **REQ-TR-06** 수용 기준: 사용자 번역(부분 포함)이 있으면 자동·사용자 번역 요청 모두 AI 호출 0회, 늦게 도착한 AI 결과가 표시를 바꾸지 않음.
- **REQ-TR-07** 수용 기준: 발음 없음 → 번역 재생성 없음. 발음은 "발음 생성" 명시 요청으로 별도 호출.
- **REQ-TR-08** 수용 기준: 재번역은 명시 요청만, 새 버전 저장, 이전 버전 보존, 사용자 번역 우선 유지.
- **REQ-TR-09** 수용 기준: 동시 요청 1회 호출, 결과·작업 상태 원자적 저장, 곡 변경 후 이전 곡 응답이 현재 화면에 한순간도 섞이지 않음.
- **REQ-TR-10** 수용 기준: 타임아웃·앱 종료로 결과 미확인 → 자동 재요청 0회, 사용자 확인 후에만 재요청. 중복 과금 경계를 docs/security.md에 기록.

- **REQ-TR-12** 수용 기준: 프롬프트가 문맥·반복·추가 금지·혼합 언어 규칙을 포함. 품질은 MV-AI-02 평가표로 확인. 긴 가사(기본 400행·12,000자 초과)는 현재 요청하지 않음(분할 번역은 Phase 5).

### 사용자 편집
- **REQ-ED-01** 수용 기준: 직접 입력·붙여넣기로 행별 번역 저장·수정, 부분 번역 허용, 존재하지 않는 행 ID 거부.
- **REQ-ED-02** 수용 기준: TXT는 행 수가 같을 때만 순서대로 제안, LRC는 시간이 ±50ms로 일치하는 행만 제안. 불일치 시 자동 매핑 없이 수동 연결. UTF-8 아님 의심 시 경고.
- **REQ-ED-04** 원문 TXT 내보내기(2026-10-05 사용자 요청). 수용 기준: 현재 곡 원문을 한 줄씩(연 구분 빈 줄 유지, 시간·번역·발음 없음) UTF-8 TXT로 만들어 공유 시트로 내보낸다. 파일 이름은 "제목 - 가수 (원문).txt"(금지 문자 제거). 내보낸 줄 순서대로 번역한 텍스트를 "번역 직접 입력"에 붙여 넣으면 행이 맞는다. 연주곡은 내보내지 않는다.
- **REQ-ED-05** 플레이리스트 번역 묶음 파일(2026-10-06 사용자 요청 "수십 곡을 일일이 눌러 번역을 넣기 힘들다 → 수작업 번역을 플레이리스트에 일괄로", 방식 선택 "플레이리스트 묶음 파일", 기존 번역 "건너뛰기"). 수용 기준: 플레이리스트 화면에서 가사 원문이 저장돼 있고 "내 번역"이 없는 곡만 골라 TXT 한 파일(곡마다 `### 번호. 제목 — 가수  {lv:판본ID}` 머리글 + `[원문]` + 빈 `[번역]`)로 공유 시트에 내보낸다(가사 없는 곡·연주곡·한국어 곡·중복은 빼고 개수를 알림). 번역을 채운 파일(또는 붙여 넣은 내용)을 가져오면 머리글의 판본 ID로 곡을 정확히 찾고(제목으로 추측하지 않음), 곡마다 "번역 직접 입력"과 같은 규칙(빈 줄 제외 줄 수가 원문과 같을 때만)으로 맞춘 미리보기를 보여 준다. 사용자가 "저장"을 누르면 적용 가능한 곡마다 새 "내 번역" 버전이 추가된다(곡마다 원자적, 이전 버전 보존, AI 번역보다 우선). 이미 내 번역이 있는 곡(미리보기 뒤에 생긴 경우 포함)·줄 수 다름·번역 비어 있음·원문 그대로·이 기기에 없는/내보낸 뒤 바뀐 판본·중복은 저장하지 않고 이유를 표시한다. 파일은 불신 데이터(크기·곡 수 제한, 번역 칸의 지시문을 따르지 않음). AI·네트워크를 쓰지 않는다.
- **REQ-ED-03** 수용 기준: 행별 한글 독음 수정이 AI 발음보다 우선하고 재실행 후 유지.

### 저장
- **REQ-ST-01** 수용 기준: 원문·발음·번역·보정값을 SQLite에 저장, 같은 곡 재생 시 저장본 사용(LRCLIB·AI 호출 0회).
- **REQ-ST-02** 수용 기준: 오프라인에서 저장된 곡 가사·번역 표시.
- **REQ-ST-03** 수용 기준: DB는 캐시가 아닌 앱 문서 영역에 저장. 마이그레이션은 트랜잭션·롤백, 사용자 데이터 보존, 앱보다 새 스키마는 열지 않음.
- **REQ-ST-04** 수용 기준: 백업 파일 하나로 가사·번역·발음·보정값·곡 연결을 옮길 수 있다. 새 설치본에 가져오면 같은 곡에서 AI·가사 요청 없이 같은 번역이 보인다. 기존 데이터는 지우거나 고치지 않고, 같은 곡이 양쪽에 있으면 사용자 번역이 있는 쪽을 보인다. 해시·형식·참조가 맞지 않는 파일은 전체 거부하고, 가져오기 도중 실패하면 아무것도 반영하지 않는다. API 키·제공자 설정·자동 번역 동의는 백업에 넣지 않는다.
